- Firebase RTDB security rules live in `security/firebase-rules.json` (original in `firebase-rules-original.json`) and are applied only through the email Worker's `POST /db-rules` (RULES_KEY secret header; uses its FIREBASE_DB_SECRET and backs up the previous rules to locked `secure/rulesBackups` first) — the owner never edits rules by hand and every lock can be rolled back. Locking is staged: unnamed top-level paths stay open via `$top` until their callers are moved to signed-in or Worker access.
- Passwords are checked and saved only by the email Worker `password` action (`passwordLogin`/`changePassword`/`savePasswordWithCode`/`googleSetPassword` in `src/lib/emailService.ts`); hashes (PBKDF2) live in locked `secure/credentials/{node}/{key}` and the site never reads a `password` field. Until `secure/authConfig/stripLegacy` is true the Worker keeps the old plain field in sync, because the published build may still be the old one; set it (after Publish + bulk hash) to delete plain fields.
