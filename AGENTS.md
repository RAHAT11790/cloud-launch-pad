- Subdirectories have their own `AGENTS.md` (e.g. `src/lib/mkv/`); read it before changing files there.
- Profile shop frames animate via CSS layers in `src/components/profile/AnimatedFrame.tsx` (effects stored as a comma string, "none" = still) and backdrops render through `BackdropMedia.tsx` (image or muted looping video with poster fallback) — keeps every frame/backdrop surface (profile, shop, admin preview) identical and compositor-cheap.
- Profile backdrop media: gallery uploads are stored as base64 chunks in Firebase `profileMedia/{id}` (items reference `rtdb:{id}`), downloaded over RTDB REST (never the realtime socket, which it would block) and persisted in Cache Storage via `src/lib/profileMediaStore.ts`; shop, customization and a first-frame poster are mirrored in localStorage and read synchronously — instant correct paint on return, public storage buckets are blocked.
- Decorative backdrop videos carry `data-bg-media`; every "stop all playback" sweep must use `video:not([data-bg-media])`, and `public/sw.js` may only delete its own old `rs-image-cache-*` caches — otherwise the profile video gets emptied or its cache wiped.
- Category emoji + motion for pills, rail titles and New Release live only in `src/lib/categoryFx.ts` + `CategoryLabel.tsx` (transform/opacity CSS `cat-*`) — one look everywhere, cheap on low-end phones.
- Share links carry the real episode number as `?ep=N` (combo-aware); `?e=` stays the legacy list position and the app maps `ep` to a position after loading the full episode list — combo entries make numbers and positions differ.
- Live TV visibility is one Firebase flag (`settings/liveTvEnabled`, missing = on) read via `src/lib/liveTvToggle.ts`; the swipe pages and bottom menu both derive from `mainPagesFor()` so they never disagree.
- Main tabs in `src/pages/Index.tsx` are stacked absolute pages (visited ones stay mounted, parked with `opacity:0` + `content-visibility:hidden`, never `visibility` or root-level attribute changes, which restyle every node); a tab change animates only the outgoing and incoming page with the `pg-in-*`/`pg-out-*` CSS classes, and Profile uses the same horizontal motion — no strip translate, so far tabs never mount or paint the pages in between; grid/row cards are memoized with a stable click callback so tab switches don't re-render them.
- Standalone HTML exports bundle the existing MKV demux/audio-sidecar/subtitle reader without Firebase or edge-router dependencies; preserve host template variables and use only same-host/direct CORS-capable range reads, so exports do not leak app settings or require new services.
- Season ranges live in `src/lib/seasonRanges.ts`: the whole series is counted as one list, cut by ranges, and continuous numbering stores `episodeStart` on the season so renumbering after edits keeps 41..80 — the player just shows each episode's stored number.
- Free website downloads select episodes in the existing player sheet before navigating to `/download`; premium dispatch stays in that sheet. Download ads execute in a disposable same-origin document with provider-only script URLs, and reaching final links reloads the parent document to destroy all advertiser hooks. Settings remain in Firebase and filename URLs resolve only through the `file-rename` router row for both HTTP and HTTPS.
- Guest-specific Firebase SDK operations are routed through `firebase.ts` into one localStorage document using `guestPersistence.ts`; only `guestRegistry/{id}=true` goes remotely, so sibling history/wallet/profile paths cannot accidentally persist guest records. This is data routing, never an authorization boundary.
- Playback clicks hydrate current Firebase rows before opening, resume targets map stored episode numbers through `resumeTarget.ts`, and REST caches expire quickly; this prevents editor link/range changes from leaving stale playback URLs.
- Download steps snapshot resolved admin settings once (chosen per selected-episode count by `downloadStepsFor`); each preparation countdown is separate from the sponsor visit, and sponsor returns are consumed once before advancing to prevent duplicate steps. The current step and its wall-clock start are saved per download in sessionStorage, so leaving and returning resumes the countdown instead of restarting it.
- In-app closes go back only within the current page load (`src/lib/historyBoot.ts`); older history entries (before the standalone download page) would reload the whole site, so closes navigate instead. Returning from the download page shows `BackToWatchLoader` (also pre-painted from index.html) until the player is ready.
- Browser eligibility is centralized in browserEligibility.ts (synchronous userAgentData brand check, admin paths exempt) and enforced inside the router before route content mounts; this keeps unsupported-browser actions and identity consistent with no waiting screen.
- Route-backed navigation must preserve React Router history metadata and wait for routed content before painting a main tab; synthetic history guards cause incorrect back targets.
- Telegram batch endpoints are expanded centrally into inclusive ranges, while episode actions build single-episode payloads; direct media sources remain independent.
- Bell items come only from `src/lib/announcements.ts` (Firebase `announcements` + live `newEpisodeReleases`), and online counts only from `src/lib/presence.ts` (`presence/{r_uid|g_device}` = {k,t}, removed on disconnect/hidden) — one place decides expiry, one-time popups and real/guest liveness without touching user profiles.
- Chrome-only gate switch, IP allow list and Device ID allow list live in Firebase `settings/browserGate`, decided only by `browserGateBlocks` in `src/lib/browserAccess.ts` (missing switch = on, cached locally); the gate Device ID comes from hardware traits only so it survives IP/Wi-Fi changes — one tested place decides who may bypass the gate.
- Laptop/PC/TV layout is one CSS layer at the end of `src/index.css` (`min-width:960px`, which also catches phone "Desktop site" mode at 980px but no phone in normal mode) keyed on stable hook classes (`site-header`, `nv-bar`, `rail-*`, `tab-page`, `rs-player-layout/info/side`, `rs-ep-*`, `rs-inline-sheet`, `admin-*`); the player video gets an explicit width/height from `--pl-w` (percent width + aspect-ratio collapses its grid row), and short or portrait large screens use one column — mobile stays untouched and large-screen fixes never need JSX forks.
- Player remote/keyboard keys are decided only by `remoteActionFor` in `src/lib/remoteKeys.ts` and handled by one window-capture listener in `VideoPlayer.tsx` (runs before the TV focus navigator); Live TV passes `remoteChannels`, series step through `episodeList` — one tested place maps Android TV/Tizen/webOS/PC keys, and the side remote rail is CSS-hidden on phones.
- Routed functions resolve via `getEdgeFunctionUrl`, which drops rows whose server is dead (`src/lib/routeHealth.ts`: one side-effect-free probe per origin, cached on device); sync route caches check `isRouteKnownDead` — a dead function server must act like an empty router row, and no code may hard-code a backend URL fallback.
- Player pop-unders count as shown only when a sponsor tab really opened (`tagOpenedSince` in `src/lib/adsterraAds.ts`); a silent tag is capped for `TAG_RETRY_MS` and the Direct Link takes over, so ads keep running in long sessions.
- Adsterra analytics goes only through the EGD-routed `adsterra-stats` row (`cloudflare-workers/adsterra-stats.js`) so admin works when Cloud is down.
- Global chat (`src/lib/communityChat.ts`) is one public RTDB room keyed by the app's own account IDs (guests read only); `buildMessage` is the single gate for allowed kinds (text/image/voice/sticker, never video), voice notes are stored separately and fetched over REST — no private rooms exist because the RTDB is publicly readable.
- Custom download servers (`settings/downloadManager/customServers`) join the Video Servers list and share its HTTP/HTTPS switch — one URL rewrite path.
- Cloudflare Manager redeploys pass existing Worker secrets as `inherit` bindings, or an older live manager wipes them.
- Player ad back-lock lives only in `src/lib/adBackLock.ts` (window-capture popstate swallow + `history.forward()`, no synthetic history entries) with the `AdLoadingLock` overlay; Chrome skips auto-redirect history entries, so a sponsor tab itself can never be back-locked.
- The selected download server is probed via `routeHealth` and skipped while dead (`applyActiveDownloadServer`); the download page tries active-server then the file's own server per file — an offline tunnel must never block healthy files.
