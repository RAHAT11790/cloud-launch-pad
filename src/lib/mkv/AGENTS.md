- Embedded tracks live in `src/lib/mkv/*` + `useEmbeddedTracks`: every direct file is sniffed by its bytes (MKV vs MP4, names lie); playback always starts natively and the native MKV audio is the FIRST track (browsers ignore the default flag); subtitles with the original audio use the side-reader (`subtitleReader.ts`); a different audio language uses the full MSE engine only for non-HEVC video that showed a picture, otherwise `audioSidecar.ts` streams just that audio beside the untouched native video — byte reads go DIRECT to HTTPS hosts first (`directCorsCandidates`: RS hosts send CORS+Range), then the per-server proxy, then the EGD `video-proxy` (`src/lib/trackProxy.ts`, cached locally; hosts that refused a direct read are remembered per device so later reads go proxy-first), so tracks keep working on no-CORS servers and HEVC files never go black. The video itself never plays through `video-proxy`; the header is pre-read ~300ms after the track list is known so switches start instantly.
- Subtitle names come from a one-time scan of the real lines (`src/lib/mkv/subtitleScan.ts` via `refineSubtitleLabels`), saved in the shared track cache with `scanned: true` — file tags are often wrong and sparse tracks are signs-only, and only the first viewer of a file pays the read.
- Default-audio choice for in-file tracks lives in `src/lib/mkv/audioDefault.ts` (per-file pick > Hindi > last global pick), and the AN audio pick is session-only — one tested place decides what a fresh open plays.
- Dolby/DTS/TrueHD (and FLAC/PCM/MP2) tracks are decoded by the WASM FFmpeg-decoder build in `src/lib/mkv/wasm/` (source `rsaudio.c`; rebuild with emscripten against FFmpeg with only those decoders + swresample) inside `audioDecode.worker.ts`, re-wrapped as 48 kHz stereo FLAC-in-MP4 (`flacPcm.ts`, `pcmFeeder.ts`) and played by the same `AudioSidecar`; a silent native Dolby first track (`decodeNative`, or zero `webkitAudioDecodedByteCount`) is played the same way — browsers never decode these codecs and the video must stay native.
- Black-picture MKV (HEVC/10-bit) is drawn by `PictureDecoder` (worker: hardware WebCodecs first, WASM `rsvideo` fallback, WebGL paint, timing in `pictureCore.ts`); a file that opens with `videoWidth 0` is held silent and handed over at once by `useEmbeddedTracks` — sound must never run ahead of the picture.
