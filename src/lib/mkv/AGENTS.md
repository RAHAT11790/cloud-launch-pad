- Embedded tracks live in `src/lib/mkv/*` + `useEmbeddedTracks`: every direct file is sniffed by its bytes (MKV vs MP4, names lie); playback always starts natively and the native MKV audio is the FIRST track (browsers ignore the default flag); subtitles with the original audio use the side-reader (`subtitleReader.ts`); a different audio language uses the full MSE engine only for non-HEVC video that showed a picture, otherwise `audioSidecar.ts` streams just that audio beside the untouched native video — byte reads go DIRECT to HTTPS hosts first (`directCorsCandidates`: RS hosts send CORS+Range), then the per-server proxy, and only then the EGD `video-proxy`, so tracks keep working with no backend server and HEVC files never go black.
- Subtitle names come from a one-time scan of the real lines (`src/lib/mkv/subtitleScan.ts` via `refineSubtitleLabels`), saved in the shared track cache with `scanned: true` — file tags are often wrong and sparse tracks are signs-only, and only the first viewer of a file pays the read.
- Default-audio choice for in-file tracks lives in `src/lib/mkv/audioDefault.ts` (per-file pick > Hindi > last global pick), and the AN audio pick is session-only — one tested place decides what a fresh open plays.
