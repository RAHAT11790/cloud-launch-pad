- Chat moderation rules (filters, links, ban times, commands, slow mode, CEO check) live only in `chatModeration.ts`; client-enforced since the RTDB is public.
- Sign-up/reset emails go only through EGD row `email-service` (SMTP worker, port 465 TLS via `cloudflare:sockets`, Deno copy injects `__rsOpenTls`; `cloudflare-workers/email-service.js`; the Supabase copy is the same code + Deno adapter, kept equal by a test) via `src/lib/emailService.ts` (also the admin email-domain/guest rule from `settings/loginAccess`, mirrored in the Worker, + login-first flag). Each request is one hashed, single-use ticket in Firebase `emailAuth/tickets`, HMAC-sealed over all fields and changed only by ETag-conditional writes (rate counters and final states are also shadowed in Worker memory), so edited/rolled-back records are refused and a code works once; accounts are written only after a verified code, and a reset needs an `appUsers` record with an `id` (checked by Worker and site). Emails are code-only — no links, buttons, images or web addresses, and the SMTP conversation uses only the mail provider's own names — because each mixed domain is a spam signal on a shared sender. Open code screens are saved on device (`rs_pending_register` / `rs_pending_reset` / `rs_pending_profile_reset`) and reopened after the page was closed; ✕ clears them. Limits/defaults live in the Worker `DEFAULTS`/`BOUNDS`, mirrored by `emailStats.ts` (a test keeps them equal).
- Premium-on reload is decided only by `premiumReload.ts` (inactive→active seen this visit); a page reload is the one reliable way to drop ad tags already injected. A screen still showing a result (Lucky Spin) may `holdPremiumReload()` and the reload runs on release.
- Lucky Spin rules (prize weights, spins per period counted from the first spin, coin price, stop angle) live only in `luckySpin.ts` (`settings/luckySpin`, missing = off; per user `users/{uid}/luckySpin`); the spin slot is taken before coins and given back if coins are short, so taps can't overspend.
- Player ads are released only by `AdsterraAdManager` (tap in the player) when `adPacing.ts` opens a slot; `releaseAd` in `adsterraAds.ts` uses the Adsterra pop-under and falls back to the Direct Link when the tag stays silent. Adsterra is the only ad network (admin section "Adsterra Ads"). Pop-under tags are mounted ~1.5 s before the first slot (`msUntilAdSlot` + `preloadAdTags`), because a tag injected during the tap itself misses that tap.
- The selected download server is probed via `routeHealth` and skipped while dead (`applyActiveDownloadServer`); the download page tries active-server then the file's own server per file — an offline tunnel must never block healthy files.
- Download file sizes come only from `src/lib/downloadSize.ts`: read through the same `file-rename` relay as the download (HEAD, then `Range: bytes=0-1`; never `0-0`, which hangs Telegram stream servers), sizes cached on device and failures retried after a short wait — raw file servers send no CORS and HTTP is blocked on HTTPS pages.
- Payment configuration lives in `paymentGateway.ts`: wallet plans stay in `bkashSettings.plans`, crypto plans belong to each method, and request metadata snapshots currency/device limits. `plansFor` and `paymentRequestGroup` isolate purchase, pending, admin and SMS paths without rewriting historical records.
